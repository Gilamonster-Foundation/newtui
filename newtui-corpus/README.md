# newtui-corpus

Portable behavioral conformance for newtui components. This separate, non-default
workspace package records seed + key paths → views, flows, and host-projected
intents through the existing explorer. Fingerprints remain internal.

From the repository root:

```sh
cargo run -p newtui-corpus -- export-dial > /tmp/dial.json
cargo run -p newtui-corpus -- check /tmp/dial.json
python -m pip install 'content-addressable==0.1.2'
python newtui-corpus/python/consumer.py /tmp/dial.json
(cd newtui-corpus/go && go run . /tmp/dial.json)
```

Each consumer drives its own dial implementation through all 36 recorded
observations and 24 transitions. Python does not import the newtui binding; Go
does not invoke Rust or cgo. The checked-in [JSON carrier](fixtures/dial.json)
and [canonical-byte fixture](fixtures/dial.cbor) are regenerated by the Rust
CLI test and independently verified in both foreign test suites. Wrong flow
and intent implementations are expected failures in all three languages.

Rust requires 1.88, Python requires the published `content-addressable` 0.1.2
face, and the optional Go consumer requires Go 1.26 or newer. Native consumers
currently implement only `newtui.example-dial/v1`; the Rust library is generic
and also tests the real SettingsPanel. This does not claim crush adoption.

See [the schema, content-addressing inventory, and boundary rules](../docs/corpus.md).
`just corpus-check corpus-coverage corpus-consumers` runs the explicit gates.
